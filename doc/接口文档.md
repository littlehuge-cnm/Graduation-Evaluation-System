## 1 通用约定

### 1.1 请求头

| 头部字段 | 是否必填 | 说明 |
| --- | --- | --- |
| Content-Type | 是 | `application/json`（文件上传除外） |
| Authorization | 是（登录除外） | `Bearer <JWT Token>` |

### 1.2 统一响应结构

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

| 字段 | 说明 |
| --- | --- |
| code | 状态码，200 成功，401 未认证，403 无权限，400 参数错误，500 服务器错误 |
| message | 提示信息 |
| data | 业务数据，无数据时为 null |

### 1.3 角色权限说明

| 角色 | 权限范围 |
| --- | --- |
| admin | 超级管理员，拥有全部权限 |
| teacher | 教师，按身份上下文（指导/评阅/组长/秘书）过滤数据 |
| student | 学生，仅能查看本人信息 |

### 1.4 分页参数约定

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| pageNum | int | 1 | 页码 |
| pageSize | int | 10 | 每页条数 |

分页响应结构：

```json
{
  "code": 200,
  "data": {
    "total": 100,
    "pageNum": 1,
    "pageSize": 10,
    "list": []
  }
}
```

## 2 认证模块

### 2.1 用户登录

**请求**

```
POST /api/auth/login
```

**请求体**

```json
{
  "userType": "admin",
  "username": "admin",
  "password": "admin123"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| userType | string | 是 | 用户类型：admin/teacher/student |
| username | string | 是 | 账号（管理员账号/工号/学号） |
| password | string | 是 | 密码 |

**响应**

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "userType": "admin",
    "username": "admin",
    "name": "系统管理员"
  }
}
```

### 2.2 用户退出

```
POST /api/auth/logout
```

**响应**

```json
{ "code": 200, "message": "退出成功" }
```

### 2.3 获取当前登录用户信息

```
GET /api/auth/info
```

**响应**

```json
{
  "code": 200,
  "data": {
    "userType": "teacher",
    "username": "T2026001",
    "name": "张老师",
    "identities": ["指导教师", "组长"]
  }
}
```

### 2.4 修改密码

```
PUT /api/auth/password
```

**请求体**

```json
{
  "oldPassword": "old123",
  "newPassword": "new123"
}
```

### 2.5 重置用户密码（超管）

```
PUT /api/auth/password/reset
```

**请求体**

```json
{
  "userType": "teacher",
  "username": "T2026001",
  "newPassword": "123456"
}
```

## 3 用户与基础数据管理

### 3.1 教师管理

#### 3.1.1 新增教师（超管）

```
POST /api/teachers
```

**请求体**

```json
{
  "teacherNo": "T2026001",
  "teacherName": "张老师",
  "gender": "男",
  "department": "计算机系",
  "title": "教授",
  "phone": "13800138000",
  "password": "123456",
  "accountStatus": 1
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| teacherNo | string | 是 | 工号 |
| teacherName | string | 是 | 姓名 |
| gender | string | 否 | 性别（男/女） |
| department | string | 否 | 所在院系 |
| title | string | 否 | 职称 |
| phone | string | 否 | 联系方式 |
| password | string | 是 | 登录密码 |
| accountStatus | int | 否 | 账号状态：1=启用（默认）/2=禁用 |

#### 3.1.2 修改教师（超管）

```
PUT /api/teachers/{teacherNo}
```

#### 3.1.3 删除教师（超管）

## 6 文档管理（任务书/指导书）

### 6.1 保存/更新文档（指导教师）

指导教师填写自己指导学生的任务书或指导书，支持草稿保存。

```
POST /api/documents
```

**请求体**

```json
{
  "studentNo": "2026001",
  "docType": "任务书",
  "title": "基于Spring Boot的毕业设计评价系统",
  "subjectCategory": "A",
  "subjectType": "A",
  "subjectNewOld": "A",
  "content": "课题研究主要内容与基本要求...",
  "status": 1
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| docType | string | 是 | 文档类型：任务书/指导书 |
| title | string | 任务书必填 | 题目 |
| subjectCategory | string | 任务书选填 | 课题类别 A/B/C/D |
| subjectType | string | 任务书选填 | 课题类型 A/B/C |
| subjectNewOld | string | 任务书选填 | 新旧课题 A/B |
| content | string | 否 | 正文内容 |
| status | int | 是 | 1=草稿/2=已提交 |

### 6.2 修改文档（指导教师）

```
PUT /api/documents/{id}
```

### 6.3 提交文档（指导教师）

将文档状态从 1（草稿）改为 2（已提交），学生方可查看。

```
PUT /api/documents/{id}/submit
```

### 6.4 查询文档详情

```
GET /api/documents/{id}
```

权限说明：指导教师仅能查自己学生的；学生仅能查自己的；超管可查全部。

### 6.5 按学生查询文档列表

```
GET /api/students/{studentNo}/documents?docType=任务书
```

### 6.6 查询指导教师待填写文档列表

```
GET /api/documents/my-students?docType=任务书
```

返回当前登录教师所指导学生的文档填写情况。

## 7 评价记录管理

### 7.1 录入开题成绩（组长）

```
POST /api/score-records
```

**请求体**

```json
{
  "studentNo": "2026001",
  "itemType": "开题成绩",
  "subScores": "4,3,4",
  "comment": "",
  "recordStatus": 1
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| itemType | string | 是 | 条目类型（见 7.9 条目类型表） |
| subScores | string | 否 | 分项成绩，逗号分隔 |
| score | number | 否 | 总成绩（若未传则后端按分项求和） |
| grade | string | 否 | 等级（仅委员会评定填写） |
| comment | string | 否 | 评语/记录内容 |
| recordStatus | int | 否 | 记录状态：1=暂存（默认）/2=已确认 |

权限说明：根据 itemType 自动校验当前用户身份是否匹配录入角色。`recorderNo`（录入人账号）和 `recordTime`（录入时间）由后端从 JWT 上下文自动填充，无需前端传入。

### 7.2 修改评价记录

```
PUT /api/score-records/{id}
```

权限：仅原录入人或超管可修改，需环节处于"进行中"。

### 7.3 查询评价记录详情

```
GET /api/score-records/{id}
```

### 7.4 按学生查询全部评价记录

```
GET /api/students/{studentNo}/score-records
```

**响应**

```json
{
  "code": 200,
  "data": [
    { "itemType": "开题成绩", "score": 11, "recorderNo": "T2026001", "recorderName": "张老师", "recordStatus": 2, "recordStatusDesc": "已确认" },
    { "itemType": "外文翻译", "score": 3, "recorderNo": "T2026001", "recorderName": "张老师", "recordStatus": 2, "recordStatusDesc": "已确认" }
  ]
}
```

> `recorderName` 由后端关联 `t_teacher` 表联查得到，数据库中仅存储 `recorder_no`。

### 7.5 按学生+条目类型查询

```
GET /api/students/{studentNo}/score-records?itemType=开题成绩
```

### 7.6 查询待录入列表（按角色）

返回当前登录教师需要录入的成绩列表。

```
GET /api/score-records/todo
```

例如组长调用返回本组学生的开题成绩/中期检查/答辩成绩待录入项；指导教师调用返回自己学生的外文翻译/指导评语待录入项；秘书调用返回本组答辩记录待录入项。

### 7.7 录入外文翻译成绩（指导教师）

```
POST /api/score-records
```

```json
{
  "studentNo": "2026001",
  "itemType": "外文翻译",
  "subScores": "1,1,1"
}
```

### 7.8 录入中期检查（组长）

```
POST /api/score-records
```

```json
{
  "studentNo": "2026001",
  "itemType": "中期检查",
  "subScores": "5,4,5",
  "comment": "进度正常，已完成主要模块设计。"
}
```

### 7.9 条目类型表

| itemType | 录入人 | 分项满分 | 总满分 |
| --- | --- | --- | --- |
| 开题成绩 | 组长 | 4+4+4 | 12 |
| 外文翻译 | 指导教师 | 1+1+1 | 3 |
| 中期检查 | 组长 | 5+5+5 | 15 |
| 指导评语 | 指导教师 | 3+3+3+3+3 | 15 |
| 评阅评语 | 评阅教师 | 4+4+4+3 | 15 |
| 答辩记录 | 秘书 | 无分项 | — |
| 答辩成绩 | 组长 | 10+10+10+10 | 40 |
| 委员会评定 | 超级管理员 | 加权总分 | 100 |

```json

  "itemType": "答辩记录",

```

> 答辩日期信息记录在 `comment` 正文中，`recordTime` 由后端自动填充为录入时间，与其他评价记录接口保持一致。

### 7.13 录入答辩成绩（组长）


### 7.14 录入委员会评定（超管）

```
POST /api/score-records
```

```json
{
  "studentNo": "2026001",
  "itemType": "委员会评定",
  "score": 88.5,
  "grade": "良",
  "comment": "该生毕业设计整体表现良好。"
```

说明：score 为加权总分（开题×12%+翻译×3%+中期×15%+指导×15%+评阅×15%+答辩×40%），可由后端自动计算。

## 8 环节状态管理

### 8.1 查询学生环节状态

```
GET /api/students/{studentNo}/stage-status
```

**响应**

```json
{
  "code": 200,
  "data": [
    { "stage": "开题", "status": 3, "statusDesc": "已完成", "startTime": "2026-03-01 09:00:00", "completeTime": "2026-03-10 17:00:00" },
    { "stage": "中期", "status": 2, "statusDesc": "进行中", "startTime": "2026-04-10 09:00:00", "completeTime": null },
    { "stage": "答辩", "status": 1, "statusDesc": "未开始", "startTime": null, "completeTime": null }
  ]
}
```

### 8.2 启动环节（超管）

将指定环节状态从 1（未开始）置为 2（进行中），前置环节必须为 3（已完成）。

```
PUT /api/stage-status/start
```

**请求体**

```json
{
  "studentNo": "2026001",
```

## 11 状态字段流转管理

系统共涉及 8 类状态字段，所有状态值均采用数字编码（1/2/3...）存储，接口返回时后端自动转换为中文描述。

### 11.1 状态编码总览

| 序号 | 状态名称 | 所属表 | 字段名 | 编码 |
| --- | --- | --- | --- | --- |
| 1 | 账号状态 | t_admin/t_teacher/t_student | accountStatus | 1=启用 2=禁用 |
| 2 | 学生整体进度 | t_student | overallStatus | 1=待分配 2=进行中 3=待答辩 4=已完成 5=已弃做 |
| 3 | 教师分组状态 | t_teacher_group | groupStatus | 1=待启用 2=已启用 3=已停用 |
| 4 | 师生关系状态 | t_teacher_student | relationStatus | 1=生效 2=已解除 |
| 5 | 文档状态 | t_document | status | 1=草稿 2=已提交 |
| 6 | 课题审批状态 | t_document（任务书） | approvalStatus | 1=待系审 2=系通过 3=系驳回 4=待院审 5=院通过 6=院驳回 |
| 7 | 评价记录状态 | t_score_record | recordStatus | 1=暂存 2=已确认 |
| 8 | 环节状态 | t_stage_status | status | 1=未开始 2=进行中 3=已完成 |

### 11.2 账号状态流转（account_status）

**状态机**

```
1 启用 ──禁用──→ 2 禁用
   ↑                │
   └────启用────────┘
```

**接口**

#### 11.2.1 修改账号状态（超管）

```
PUT /api/accounts/status
```

**请求体**

```json
{
  "userType": "teacher",
  "username": "T2026001",
  "accountStatus": 2
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| userType | string | 是 | admin/teacher/student |
| username | string | 是 | 账号 |
| accountStatus | int | 是 | 1=启用 2=禁用 |

**流转规则**：默认 1（启用）；超管可禁用异常账号，禁用后无法登录但数据保留；可重新启用。

### 11.3 学生整体进度流转（overall_status）

**状态机**

```
1 待分配 ──分配指导教师──→ 2 进行中 ──成绩齐备──→ 3 待答辩 ──委员会评定──→ 4 已完成
                              │
                              └──弃做──→ 5 已弃做
```

**接口**

#### 11.3.1 查询学生整体进度

```
GET /api/students/{studentNo}/overall-status
```

**响应**

```json
{
  "code": 200,
  "data": {
    "studentNo": "2026001",
    "overallStatus": 2,
    "overallStatusDesc": "进行中"
  }
}
```

#### 11.3.2 标记学生进度状态（超管）

```
PUT /api/students/{studentNo}/overall-status
```

**请求体**

```json
{
  "overallStatus": 3
}
```

| overallStatus | 说明 | 触发条件 |
| --- | --- | --- |
| 2 进行中 | 分配指导教师后 | 系统自动流转（调用师生关系接口分配指导教师时） |
| 3 待答辩 | 所有成绩录入完毕 | 超管手动标记 |
| 4 已完成 | 委员会评定完成 | 系统自动流转（录入委员会评定后） |
| 5 已弃做 | 学生放弃或延期 | 超管手动标记 |

**流转规则**：
- 新增学生默认 1（待分配）
- 分配指导教师后系统自动变为 2（进行中）
- 所有成绩录入完毕后由超管标记为 3（待答辩）
- 委员会评定完成后系统自动变为 4（已完成）
- 学生放弃或延期由超管标记为 5（已弃做）

### 11.4 教师分组状态流转（group_status）

**状态机**

```
1 待启用 ──启用──→ 2 已启用 ──停用──→ 3 已停用
```

**接口**

#### 11.4.1 修改教师分组状态（超管）

```
PUT /api/teacher-groups/{groupId}/status
```

**请求体**

```json
{
  "groupStatus": 2
}
```

| groupStatus | 说明 | 前置条件 |
| --- | --- | --- |
| 2 已启用 | 可设定环节对应关系 | 分组成员齐全 |
| 3 已停用 | 不可再分配环节 | 毕业设计周期结束 |

**流转规则**：创建默认 1（待启用）；超管启用后变为 2（已启用）方可设定环节对应关系；毕业设计周期结束后可停用为 3（已停用）。

### 11.5 师生关系状态流转（relation_status）

**状态机**

```
1 生效 ──解除──→ 2 已解除
```

**接口**

#### 11.5.1 解除师生关系（超管）

```
PUT /api/teacher-students/{id}/relation-status
```

**请求体**

```json
{
  "relationStatus": 2
}
```

**流转规则**：默认 1（生效）；设计规定指导关系本周期内不再变更，仅教师离职等特殊情况由超管解除为 2（已解除），历史成绩评语保留。

### 11.6 文档状态流转（status）

**状态机**

```
1 草稿 ──提交──→ 2 已提交
   ↑                │
   └──退回（超管）──┘
```

**接口**

#### 11.6.1 提交文档（指导教师）

将文档状态从 1（草稿）改为 2（已提交），学生方可查看。

```
PUT /api/documents/{id}/submit
```

#### 11.6.2 退回文档（超管）

将已提交文档退回为草稿状态，允许指导教师修改。

```
PUT /api/documents/{id}/rollback
```

**流转规则**：
- 指导教师保存默认 1（草稿），学生不可见
- 提交后变为 2（已提交），学生可查看，教师不可再改
- 如需修改由超管退回 1（草稿）

### 11.7 课题审批状态流转（approval_status，仅任务书）

**状态机**

```
                       ┌──系驳回（3）──┐
                       ↓                │
1 待系审 ──系通过──→ 2 系通过 ──自动进入──→ 4 待院审
                       │                          │
                       │                       院驳回（6）
                       │                          │
                       └───退回修改后重新提交─────┘
                                                  │
                                                  ↓
                                       5 院通过（终态）
```

**接口**

#### 11.7.1 系主任审核（超管代行）

```
PUT /api/documents/{id}/dept-approval
```

**请求体**

```json
{
  "approvalStatus": 2,
  "comment": "系审核通过"
}
```

| approvalStatus | 说明 |
| --- | --- |
| 2 系通过 | 通过后自动流转为 4（待院审） |
| 3 系驳回 | 驳回，需指导教师修改后重新提交 |

#### 11.7.2 院长审核（超管代行）

```
PUT /api/documents/{id}/college-approval
```

**请求体**

```json
{
  "approvalStatus": 5,
  "comment": "院审核通过"
}
```

| approvalStatus | 说明 |
| --- | --- |
| 5 院通过 | 课题正式生效（终态） |
| 6 院驳回 | 驳回，需重新走系审流程 |

**流转规则**：
- 任务书提交后进入 1（待系审）
- 系主任（超管代行）通过后自动变为 4（待院审）
- 院长（超管代行）通过后变为 5（院通过），课题正式生效
- 任一环节驳回需指导教师修改后重新提交
- 指导书无审批流程，approvalStatus 为空

### 11.8 评价记录状态流转（record_status）

**状态机**

```
1 暂存 ──确认──→ 2 已确认
  ↑                  │
  └──解锁（超管）────┘
```

**接口**

#### 11.8.1 确认评价记录（录入人）

将记录状态从 1（暂存）改为 2（已确认），锁定不可改。

```
PUT /api/score-records/{id}/confirm
```

#### 11.8.2 解锁评价记录（超管）

将已确认记录解锁退回为暂存状态，允许修改。

```
PUT /api/score-records/{id}/unlock
```

**流转规则**：
- 录入时默认 1（暂存），环节"进行中"期间可多次修改
- 录入人点击确认后变为 2（已确认），不可再改
- 环节标记"已完成"时，所有未确认记录自动转为 2（已确认）
- 如需修改已确认记录，由超管解锁退回 1（暂存）

### 11.9 环节状态流转（status）

**状态机**

```
1 未开始 ──启动──→ 2 进行中 ──完成──→ 3 已完成
                      ↑                     │
                      └──退回（超管）────────┘
```

**流转规则**：
- 默认 1（未开始）
- 超管启动后变为 2（进行中），方可录入成绩
- 成绩录入完毕由组长或超管确认后变为 3（已完成）
- 严格先后次序：
  - 开题 = 3（已完成）→ 中期可由 1 启动为 2
  - 中期 = 3（已完成）且指导评语、评阅评语均填写 → 答辩可由 1 启动为 2

**接口**：参见 [8 环节状态管理](#8-环节状态管理) 章节。
